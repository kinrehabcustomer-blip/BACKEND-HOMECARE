# KIN Homecare — ระบบหลังบ้าน

ระบบจัดการงานดูแลผู้สูงอายุ/ผู้ป่วยที่บ้านของ KIN Homecare — ตั้งแต่รับลูกค้า เปิดเคส จัดตารางกะ พนักงานเช็คอินหน้างาน ไปจนถึงสรุปค่าตอบแทนและออกใบแจ้งหนี้ ในระบบเดียว ใช้งานผ่านเว็บทั้งคอมพิวเตอร์และมือถือ

## ใครใช้ได้บ้าง

สิทธิ์คิดจาก **ตำแหน่งงาน** ของพนักงานคนนั้น ไม่ต้องตั้งค่าแยก — เปลี่ยนตำแหน่งเมื่อไหร่ สิทธิ์เปลี่ยนทันที

| กลุ่ม | ตำแหน่ง | เห็นอะไร |
| --- | --- | --- |
| **ผู้จัดการ** | manager | ทุกอย่าง รวมค่าจ้างพนักงานและกำไรของแพ็คเกจ |
| **HR** | hr | เกือบทุกอย่าง — **ยกเว้นค่าจ้าง/กำไรในหน้าแพ็คเกจและหน้าเปิดเคส** |
| **พนักงานภาคสนาม** | caregiver, assistant_nurse, practical_nurse, nurse, therapist | เฉพาะงานของตัวเอง — กะของตัวเอง เคสที่ตัวเองรับผิดชอบ ค่าตอบแทนของตัวเอง |

พนักงานภาคสนามเข้าหน้าหลังบ้าน (รายชื่อลูกค้า ใบแจ้งหนี้ ตารางราคา) **ไม่ได้เลย** ทั้งจากเมนูและจากการพิมพ์ที่อยู่เว็บตรงๆ

## เข้าใช้งานครั้งแรก

1. เปิดเว็บแล้วกรอก **อีเมล + รหัสผ่าน** ที่ผู้จัดการตั้งให้
2. ครั้งแรกระบบจะบังคับให้ **เปลี่ยนรหัสผ่าน** ก่อนใช้งาน
3. เข้าเสร็จแล้ว
   - พนักงานภาคสนาม → เด้งไปหน้า **งานวันนี้** อัตโนมัติ
   - ผู้จัดการ/HR → เข้าหน้า **แดชบอร์ด**

**ลืมรหัสผ่าน** → กด "ลืมรหัสผ่าน" ที่หน้าเข้าสู่ระบบ ระบบส่งรหัส OTP ไปที่อีเมล เอามาตั้งรหัสใหม่ได้เลย

> เข้าระบบค้างไว้ได้ **8 ชั่วโมง** (ประมาณหนึ่งกะทำงาน) ครบแล้วต้องเข้าใหม่
> พนักงานที่ลาออกหรือถูกพักงานจะเข้าไม่ได้ทันที

## สำหรับพนักงานภาคสนาม

### งานวันนี้ — หน้าหลักที่ใช้ทุกวัน

เห็นกะของตัวเองทั้งวัน แต่ละกะบอก: บ้านใคร เวลานัด ที่อยู่ และสถานะ

| สถานะกะ | หมายความว่า |
| --- | --- |
| รอเช็คอิน | ถึงเวลาแล้วยังไม่ได้กด |
| กำลังทำงาน | เช็คอินแล้ว ยังไม่เช็คเอาท์ |
| ค้างเช็คเอาท์ | เช็คอินไว้เกิน 16 ชั่วโมงแล้วลืมกดออก |
| เสร็จแล้ว | ครบทั้งเข้าและออก |
| ขาดงาน | เลยวันไปแล้วไม่มีการเช็คอิน |

### เช็คอิน–เช็คเอาท์

**เช็คอิน** — กดปุ่มบนการ์ดกะ ระบบจะขอ 2 อย่าง

1. **ตำแหน่ง GPS** — ต้องกดอนุญาตในเบราว์เซอร์
2. **รูปเซลฟี่** — ถ่ายได้แต่**ไม่บังคับ** ข้ามได้

**เช็คเอาท์** — กดตอนงานเสร็จ กะจะเปลี่ยนเป็น "เสร็จแล้ว" และเริ่มนับชั่วโมง

**สิ่งที่ควรรู้**

- **เวลาใช้เวลาของระบบเสมอ** ปรับนาฬิกาในมือถือไม่มีผล
- **เช็คอินได้เฉพาะกะที่มีนัดล่วงหน้า** ไม่มีนัด = ไม่มีปุ่มให้กด ต้องให้ผู้จัดการลงกะให้ก่อน
- **เช็คอินก่อนเวลา/หลังเวลาได้** ระบบไม่ปฏิเสธ แค่บันทึกไว้ว่าสายกี่นาที (เกิน 30 นาทีจะขึ้นให้ผู้จัดการตรวจ)
- **อยู่ไกลจากบ้านลูกค้าก็ยังเช็คอินได้** ระบบแค่ติดธง "นอกพื้นที่" ให้ผู้จัดการดู ไม่บล็อก เพราะ GPS ในเมืองหรือตึกทึบคลาดเคลื่อนได้หลายสิบเมตร (ระยะปริยาย 200 เมตร)

**GPS ไม่ทำงาน?**

- เว็บต้องเป็น **https** ถึงจะขอตำแหน่งได้ (เปิดจากลิงก์ที่บริษัทให้ ไม่ใช่พิมพ์ที่อยู่เอง)
- ถ้าเคยกด "ไม่อนุญาต" ไว้ ต้องไปแก้ที่ตั้งค่าเบราว์เซอร์ → สิทธิ์ตำแหน่งที่ตั้ง
- ในอาคาร/ลิฟต์ GPS จับได้ช้า ลองออกมาที่โล่งแล้วกดใหม่
- **ไม่มี GPS ก็ยังเช็คอินได้** ระบบจะบันทึกว่าไม่มีพิกัดและติดธงให้ผู้จัดการตรวจแทน

### เมนูอื่นของพนักงาน

- **เคสของฉัน** — เคสที่รับผิดชอบ กดดูข้อมูลผู้ป่วย **แพ้ยา แพ้อาหาร โรคประจำตัว** ได้ (ข้อมูลนี้อ่านสดจากแฟ้มเสมอ แก้แล้วเห็นทันที)
- **ปฏิทินของฉัน** — กะทั้งเดือน สีบอกสถานะ
- **ค่าตอบแทนของฉัน** — ชั่วโมงและยอดเงินของตัวเองรายเดือน

> **ยอดเงินยังไม่ขึ้น?** ค่าจ้างจะเข้ายอดต่อเมื่อ **ผู้จัดการกดอนุมัติแล้ว** เท่านั้น ส่วนชั่วโมงทำงานขึ้นทันทีที่เช็คเอาท์

## สำหรับผู้จัดการ / HR

### ลำดับงานตั้งแต่ต้นจนจบ

```
1. เพิ่มผู้ว่าจ้าง (ลูกค้า)  ─┐
                              ├─► 3. เปิดเคส ─► 4. จัดตารางกะ ─► 5. พนักงานเช็คอิน
2. เพิ่มผู้รับการดูแล (ผู้ป่วย)┘                                        │
                                                                        ▼
      8. ออกใบแจ้งหนี้ ◄── 7. ปิดเคส ◄── 6. ตรวจการมาทำงาน + อนุมัติค่าจ้าง
```

### 1–2. ลูกค้า และ ผู้รับการดูแล — คนละคนกัน

- **ผู้ว่าจ้าง** = คนจ่ายเงิน/ผู้ติดต่อ (ลูก หลาน ญาติ)
- **ผู้รับการดูแล** = ผู้ป่วยที่รับบริการจริง — **ข้อมูลสุขภาพอยู่ที่นี่เท่านั้น**

ลูกค้า 1 คนผูกผู้รับการดูแลได้หลายคน (เช่น จ้างดูแลทั้งพ่อและแม่) กรอกแค่ชื่อก็บันทึกได้ ที่เหลือเติมทีหลัง

### 3. เปิดเคส

เลือกผู้รับการดูแล → เลือกประเภทบริการ

- **Homecare** → เลือก **รูปแบบบริการ** (รายวัน/รายสัปดาห์/รายเดือน) → กลุ่มรายเดือนต้องเลือก **เกรด** ด้วย → เลือก **ระดับพนักงาน** (CG / NA / PN / RN) แล้วราคาจะเติมให้เอง
- **กายภาพบำบัด** → เลือกแพ็คเกจเหมาจำนวนครั้ง

**พิกัดสถานที่ดูแล** — กดปุ่ม "หาพิกัดจากที่อยู่" หรือปักหมุดบนแผนที่ **ถ้าไม่ตั้ง ระบบตรวจไม่ได้ว่าพนักงานไปถึงจริงไหม** (เช็คอินได้ปกติ แต่ไม่มีการวัดระยะ)

### 4. จัดตารางกะ

**1 กะ = พนักงาน 1 คน ไป 1 รอบ** วันเดียวกันมีได้หลายกะ หลายคน และคนหนึ่งไปได้หลายเคสต่อวัน

ลงได้ทีละวันหรือลงยาวหลายวันรวดเดียว (เลือกช่วงวัน + วันในสัปดาห์) — ระบบ**ตรวจให้ก่อนบันทึก**ว่าวันไหนชนกับงานอื่นของคนนั้นอยู่แล้ว

### 5–6. ตรวจการมาทำงาน — หน้า "การมาทำงาน"

มี 4 แท็บ

| แท็บ | ใช้ทำอะไร |
| --- | --- |
| **รายการต้องตรวจ** | ของที่ผิดปกติ — นอกพื้นที่ · นอกวันนัด · สายเกิน 30 นาที · ค้างเช็คเอาท์ พร้อมรูปเซลฟี่และแผนที่จุดเช็คอิน กดปิดกะ/แก้เวลา/เคลียร์ธงได้ |
| **รออนุมัติค่าจ้าง** | กะที่ทำเสร็จแล้วรออนุมัติ ติ๊กหลายกะพร้อมกันได้ — **เงินยังไม่เข้าพนักงานจนกว่าจะกดที่นี่** |
| **ประวัติเช็คอิน** | ย้อนดูทั้งหมด กรองตามคน/สถานะ/เดือน |
| **สรุปค่าตอบแทน** | ยอดรายเดือนแยกรายคน เลือกดูทีละคนได้ ดาวน์โหลดเป็นไฟล์ Excel (CSV) ได้ |

> **⚠️ ระวังเรื่องเดือน** — แท็บ "สรุปค่าตอบแทน" เปิดมาที่ **เดือนที่แล้ว** เป็นค่าเริ่มต้น (เพราะเดือนปัจจุบันยังปิดเคสไม่ครบ ตัวเลขยังไม่นิ่ง) ส่วนแท็บอื่นเปิดที่ **เดือนปัจจุบัน**
> ถ้าอนุมัติค่าจ้างแล้วยอดไม่ขึ้น **ให้เช็คก่อนว่ากำลังดูเดือนถูกหรือเปล่า** กดลูกศร `>` ไปเดือนถัดไป

**ยอดขึ้นเป็น ฿0 หรือ "ยังไม่ระบุค่าจ้าง"?** แปลว่าเคสนั้นไม่มีค่าจ้างพนักงานตั้งไว้ ต้องไปตั้งที่ **หน้าแพ็คเกจ** (ช่อง "ค่าจ้าง") หรือกรอกในเคสโดยตรง แล้วยอดจะคำนวณได้

### 7–8. ปิดเคส และออกใบแจ้งหนี้

ปิดเคสแล้วยอดค่าจ้างของทุกกะจะถูก **ตรึงเป็นตัวเลขถาวร** ปรับราคาแพ็คเกจทีหลังยอดย้อนหลังจะไม่ขยับ

ใบแจ้งหนี้มี 4 สถานะ: **ร่าง → ออกแล้ว → ชำระแล้ว** (หรือ **ยกเลิก**)

**ใบที่ยังเป็น "ร่าง" หรือ "ออกแล้ว" ยังแก้ได้** และจะถูก**ปรับตามอัตโนมัติเมื่อแก้ข้อมูลเคส** (ราคา ผู้จ่าย ที่อยู่) — ตราบใดที่ยังไม่ได้รับชำระ ก็ถือว่าเอกสารยังอยู่ในมือเรา
**ใบที่ "ชำระแล้ว" หรือ "ยกเลิก" แตะไม่ได้ทุกกรณี** เงินเข้ามือแล้วยอดกลายเป็นข้อเท็จจริง ต้องยกเลิกแล้วออกใบใหม่แทน

> ⚠️ ถ้าส่งใบให้ลูกค้าไปแล้วแล้วมาแก้ราคาเคสทีหลัง **ยอดในใบจะขยับตาม** — ตรวจใบอีกครั้งก่อนเก็บเงิน หรือกดรับชำระเพื่อล็อกยอดไว้

### แพ็คเกจและราคา

- **แพ็คเกจ Homecare** — ตารางราคา เกรด × รูปแบบบริการ × ระดับพนักงาน · กด "แก้ไขราคา" เพื่อแก้ทีละหลายช่องแล้วบันทึกรวดเดียว
- **แพ็คเกจกายภาพบำบัด** — คอร์สเหมาจำนวนครั้ง ตั้งราคาเต็ม + ส่วนลด ระบบคิดราคาสุทธิและราคาต่อครั้งให้

> **ค่าจ้างพนักงานและกำไร เห็นได้เฉพาะตำแหน่งผู้จัดการ** — HR เปิดหน้านี้ได้และแก้ราคาลูกค้าได้ตามปกติ แต่จะไม่เห็นช่องค่าจ้าง/กำไร และแก้ราคาโดยไม่ทำให้ค่าจ้างเดิมหาย

### อีเมลสรุปประจำวัน

ทุกเช้า **08:00** ระบบส่งอีเมลให้ผู้จัดการและ HR ทุกคน สรุปเฉพาะของค้าง:

กะวันนี้ที่ยังไม่มีคนไป · ค้างเช็คเอาท์ · ขาดงานย้อนหลัง 14 วัน · เช็คอินที่ต้องตรวจใน 24 ชม. · ใบแจ้งหนี้เลยกำหนด

| คำ | หมายความว่า |
| --- | --- |
| **เคส** | งานดูแล 1 งาน = ผู้รับการดูแล 1 คน + แพ็คเกจ 1 แบบ + ช่วงเวลา |

| **snapshot** | เคสคัดลอกข้อมูลลูกค้า/ราคาไว้ในตัวเอง แก้ต้นทางทีหลังเคสเก่าไม่เปลี่ยนตาม |

## หลักการออกแบบสำคัญ

**1. ID ที่ระบบออกให้เอง เป็นกุญแจอ้างอิงเดียว**
`EMP-0001` `CUS-0001` `PAT-0001` `CASE-0001` `INV-0001` — ออกโดยตาราง `id_counters` (เดินหน้าเสมอ ไม่วนใช้ซ้ำแม้ลบแถวไปแล้ว) **ห้ามใช้ชื่อ/เลขบัตรเป็นตัวอ้างอิง และ `employee_id` ห้ามแก้หลังสร้าง** — API จึงไม่เปิดให้แก้

**2. แยก "ผู้ว่าจ้าง" ออกจาก "ผู้รับการดูแล"**
`customers` = คนจ่ายเงิน · `patients` = ผู้ป่วยจริง — ลูกค้า 1 คนอาจจ้างดูแลหลายคน **ข้อมูลสุขภาพอยู่ที่ `patients` เท่านั้น**

**3. เคสเก็บ snapshot ข้อมูล ณ วันเปิดเคส**
เคสคัดลอกข้อมูลลูกค้า/ผู้ป่วย/ค่าบริการมาเก็บในตัวเอง ไม่อ่านสด — เคสที่ปิดแล้วจึงคงข้อมูล ณ วันให้บริการไว้ถูกต้องแม้ต้นทางถูกแก้หรือลบ (FK เป็น `ON DELETE SET NULL`)

**4. สถานะเคสถูกบังคับให้สอดคล้องกับความจริงระดับฐานข้อมูล**
CHECK constraint กันไม่ให้เกิดเคส "จับคู่แล้ว/กำลังให้บริการ" ที่ไม่มีพนักงาน — และเปลี่ยนสถานะผ่าน endpoint เฉพาะเท่านั้น (แก้ field `status`/`assigned_to` ตรงๆ ไม่ได้)

**5. ค่าตอบแทนคิดที่ "กะที่ทำจริง" ไม่ใช่ "เคสที่ปิด"**
ยอดต่อกะ = `case_visits.staff_pay` ถ้าตั้งไว้ ไม่ตั้งก็เกลี่ยจาก `cases.staff_pay` ÷ จำนวนกะที่นัด — นับให้**คนที่เช็คอินจริง** ใน**เดือนที่เช็คอิน** และ**ตรึงเป็นตัวเลขถาวรตอนปิดเคส** เปลี่ยนพนักงานกลางคันหรือเคสลากข้ามเดือนแล้วยอดยังตกถูกคน ถูกเดือน

**6. เงินต้องผ่านมนุษย์ก่อนเข้ายอด**
`case_visits.pay_status` = `pending` → `approved`/`rejected` · **ชั่วโมง**นับทุกกะที่เช็คเอาท์แล้ว แต่ **เงิน**นับเฉพาะกะที่ `approved` (`DONE` / `PAYABLE` / `AWAITING` ใน [cases/repo.js](server/src/cases/repo.js)) การอนุมัติแตะเฉพาะกะที่ยังรออยู่ กดซ้ำหรือกดจากหน้าที่ข้อมูลเก่าจึงไม่ทับผลที่ตัดสินไปแล้ว

**7. Geofence เป็นธง ไม่ใช่ประตู**
ระยะคำนวณด้วย Haversine ฝั่ง server ([lib/geo.js](server/src/lib/geo.js)) ไม่เรียก Google — เกินรัศมี (ปริยาย `DEFAULT_GEOFENCE_M = 200`) แค่ตั้ง `location_flagged` ไม่บล็อกการเช็คอิน เพราะ GPS คลาดเคลื่อนได้จริง · เวลาใช้ `now()` ของ server เสมอ ปลอมจากเครื่องผู้ใช้ไม่ได้

**8. ทุกการเปลี่ยนสถานะของเคสถูกบันทึกว่าใครทำ**
`case_events` เก็บทีละครั้ง (เปิด/แก้/จับคู่/ถอด/เริ่ม/ปิด/ยกเลิก/เปิดใหม่/แก้กะ/อนุมัติค่าจ้าง) พร้อมชื่อผู้ทำ ณ ตอนนั้น — เขียนใน transaction เดียวกับการเปลี่ยนแปลงเสมอ

**9. ข้อมูลความปลอดภัยของผู้ป่วยอ่านสด ไม่ใช่ snapshot**
ราคา/ผู้จ่าย = snapshot (ต้องไม่ขยับ) แต่ **แพ้ยา / แพ้อาหาร / โรคประจำตัว อ่านสดจาก `patients`** — แก้แล้วคนที่กำลังจะเข้าบ้านเห็นทันที และเคสจะขึ้นป้ายว่า snapshot เดิมไม่ตรงแล้ว

**10. สิทธิ์คิดจากตำแหน่ง และมีชั้นย่อยกว่า admin**
`roleForPosition()` → `admin` (manager, hr) / `field` · เพิ่ม **`canSeeStaffPay()` = manager เท่านั้น** สำหรับต้นทุน/กำไรของแพ็คเกจ ([lib/auth.js](server/src/lib/auth.js)) — **ตัดฟิลด์ออกจาก payload จริง ไม่ใช่ซ่อนด้วย CSS** และกันการเขียนทับด้วย: ไม่มีคีย์ `staff_pay` = ไม่แตะของเดิม ต่างจากส่ง `null` = ตั้งใจล้าง

**11. SQL รวมอยู่ที่เดียว**
คำสั่ง SQL ทั้งหมดอยู่ใน [server/src/db/](server/src/db/) และ `repo.js` ของแต่ละโมดูล — route/validation/หน้าเว็บไม่แตะ SQL · `repo.js` ไม่รู้จัก HTTP (ไม่มี `ApiError` เลยสักตัว)

### วงจรสถานะเคส

```
ยังไม่จับคู่ (unassigned) ──จับคู่──► จับคู่แล้ว/รอเริ่ม (assigned) ──เริ่ม──► กำลังให้บริการ (in_progress)
                                            │                              │
                                            └──────────► ปิดเคส (closed) ◄─┘
   ทุกสถานะที่ยังไม่จบ ──ยกเลิก──► ยกเลิก (cancelled)
   closed / cancelled ──เปิดใหม่──► กลับเป็น unassigned / assigned
```

### สถานะกะ (คำนวณตอนอ่าน ไม่เก็บใน DB)

| GET/POST/PATCH/DELETE | `/physio/packages` + `/reorder` | แพ็คเกจกายภาพ + จัดลำดับ |
| GET | `/invoices/` `/:id` `/summary` `/revenue` `/meta` | รายการ/รายละเอียด/สรุป/รายได้ |
| POST | `/invoices/` `/:id/refresh` `/:id/issue` `/:id/pay` `/:id/cancel` | สร้าง · คำนวณใหม่ · ออก · รับชำระ · ยกเลิก |
| GET | `/notify/daily-digest` `/notify/digest-preview` | ส่งสรุป (cron หรือ manager) · ดูของค้างโดยไม่ส่งอีเมล |

**ค่า enum หลัก**
- `position` = caregiver, assistant_nurse, practical_nurse, nurse, therapist, manager, hr
- `employment_type` = fulltime, parttime, contract, daily
- พนักงาน `status` = active, probation, on_leave, suspended, resigned
- เคส `status` = unassigned, assigned, in_progress, closed, cancelled
- ผู้รับการดูแล `status` = active, inactive
- ใบแจ้งหนี้ `status` = draft, issued, paid, cancelled
- ระดับพนักงาน (แพ็คเกจ) = **CG, NA, PN, RN**
- หมวดรูปแบบบริการ = daily, weekly, monthly (**เฉพาะ monthly ที่ `graded = true`**)
- `pay_status` ของกะ = pending, approved, rejected

## Data model

| ตาราง | หน้าที่ |
| --- | --- |
| `employees` | พนักงาน (PK `employee_id`) + auth (password_hash, role) + รูป (`photo_data` BYTEA) |
| `employee_certificates` · `employee_portfolio` | ใบรับรอง / ผลงาน — รูปเก็บเป็น BYTEA (ไม่มี file storage ภายนอก) |
| `customers` | ผู้ว่าจ้าง (PK `customer_id`) |
| `patients` | ผู้รับการดูแล (PK `patient_id`) — FK → customers |
| `cases` | เคส (PK `case_id`) — snapshot + พิกัด/รัศมี geofence + FK → employees/customers/patients/แพ็คเกจ |
| `case_visits` | **1 แถว = 1 กะ ของพนักงาน 1 คน** — แผน (ใครไป/เวลานัด/ค่าจ้างกะ) + ของจริง (เช็คอิน-เอาท์ พิกัด ระยะห่าง รูป สาย นอกวันนัด) + สถานะอนุมัติค่าจ้าง |
| `case_events` | audit log ของเคส — ใครทำอะไร เมื่อไหร่ |
| `pkg_grades` · `pkg_service_formats` · `pkg_rates` | ตารางราคา Homecare (เกรด × รูปแบบ × ระดับ) |
| `physio_packages` | แพ็คเกจกายภาพบำบัด |
| `invoices` · `invoice_items` | ใบแจ้งหนี้ + รายการย่อย (มีเฉพาะใบที่ออกตามกะที่ไปจริง) |
| `password_reset_otps` | OTP รีเซ็ตรหัส (เก็บเป็น hash) |
| `id_counters` | ตัวนับออก ID รันนิ่ง |

schema ทั้งหมดพร้อมคำอธิบายทุกคอลัมน์อยู่ที่ [server/src/db/schema.sql](server/src/db/schema.sql) — เป็น migration แบบ additive (`CREATE TABLE IF NOT EXISTS` + `ALTER ... IF EXISTS`) รันซ้ำได้เสมอไม่ทับของเดิม

## Deploy (Vercel)

- [vercel.json](vercel.json) — build ด้วย `client` (`outputDirectory: client/dist`), rewrite `/api/*` ไป serverless function, ที่เหลือ fallback เป็น SPA
- [api/index.js](api/index.js) — จุดเข้า serverless: `export default createApp()` (Express app เป็น `(req, res)` handler อยู่แล้ว)
- [server/src/db/index.js](server/src/db/index.js) — pool เล็ก (`max: 3`) ให้เหมาะกับ serverless + โควตา connection ของ Neon
- push ขึ้น `main` แล้ว Vercel deploy อัตโนมัติ
- **Cron** — เรียก `/api/notify/daily-digest` ทุกวัน 01:00 UTC (08:00 ไทย) · ต้องตั้ง `CRON_SECRET` ไม่งั้นถูกปฏิเสธ

**เช็คลิสต์ก่อนขึ้น production**

- [ ] ตั้ง `CORS_ORIGIN` เป็นโดเมนจริง (ค่าเริ่มต้นชี้ localhost)
- [ ] ล็อก restriction ของ Google Maps key ทั้ง 2 ใบ — browser key = HTTP referrer, server key = Geocoding API เท่านั้น
- [ ] ตั้ง `CRON_SECRET` และ SMTP ให้ครบ
- [ ] ทดสอบเช็คอินบนมือถือจริง (GPS ต้องการ https)

## ข้อควรรู้ก่อนแก้โค้ด

- **มีชุดทดสอบแล้ว แต่ยังไม่ครอบทุกอย่าง** — `npm test` (ตรรกะล้วน ไม่แตะ DB) · `npm run test:api` (ยิง API จริง อ่านจากฐานที่ `.env` ชี้อยู่ **เฉพาะ GET**)
  ยังไม่ครอบเส้นทางที่เขียนข้อมูล (ปิดเคส · ลบเคส/กะ · แก้ตำแหน่ง) เพราะยังไม่มีฐานข้อมูลสำหรับเทสแยก — แก้ตรงที่เกี่ยวกับเงิน (`VISIT_PAY`, `PAYABLE`, `attendanceReport`) ยังต้องตรวจด้วยมือ
  **ห้ามเพิ่มเทสที่เขียนข้อมูลลงใน `test/api.test.js`** จนกว่าจะชี้ `DATABASE_URL` ไปฐานอื่น — ตอนนี้มันชี้ production
- **`cases/repo.js` ยาว ~1,500 บรรทัด** รวมเคส + กะ + เช็คอิน + การมาทำงาน + payroll ไว้ด้วยกัน
- **อย่าทดสอบด้วยการเขียนลง DB production** — ใช้ query อ่านอย่างเดียว หรือ `EXPLAIN` เพื่อตรวจ SQL
- ตัวแปลง `:name` ใน [db/index.js](server/src/db/index.js) ไล่หาชื่อจาก SQL ที่มีอยู่จริงเท่านั้น — ส่งพารามิเตอร์เกินมาไม่พัง แต่ขาดจะพัง
